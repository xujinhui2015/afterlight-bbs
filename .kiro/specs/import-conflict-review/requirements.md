# 需求：导入冲突预览

状态：待 Kiro 审查和实现。本规格由 Codex 准备，不表示 Kiro 已执行。

## 目标

社区成员通过 JSON 文件交换公告时，同一公告可能已经在本地被修改。用户需要在写入前看到新增、重复和冲突，并自主选择冲突版本。

## 验收条件

1. 当用户选择有效 JSON 文件时，系统应先分析其内容并展示新增、重复和冲突的数量，分析阶段不得修改本地公告。
2. 当导入条目的 ID 在本地不存在时，系统应将其归类为新增。
3. 当条目 ID 相同且所有业务字段相同时，系统应将其归类为重复，确认导入后不得生成额外副本。
4. 当条目 ID 相同但业务字段不同时，系统应列出本地版与导入版的差异，并默认保留本地版。
5. 当用户为冲突选择采用导入版并确认时，系统应仅替换选中的冲突条目，并加入新增条目，其他本地公告保持不变。
6. 当用户取消、关闭预览或文件校验失败时，系统应保留原数据并给出可读反馈。
7. 当文件内部出现重复 ID 时，系统应拒绝导入并解释原因，避免由文件顺序隐式决定数据。
8. 当用户通过键盘操作预览对话框时，系统应支持焦点导航、明确的字段标签与关闭后焦点恢复。
9. 当离线使用已经缓存的应用时，导入预览与确认流程应保持可用。
