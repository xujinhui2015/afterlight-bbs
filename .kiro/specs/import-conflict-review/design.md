# 设计草案：导入冲突预览

状态：待 Kiro 审查。具体函数名、结构与界面应在阅读现有实现后确定。

## 纯函数分析

新增 `analyzeImport(existing, incoming)`，对已经通过完整校验的数据进行比较，返回 `added`、`unchanged` 和 `conflicts`。冲突包含同一 ID 的本地版、导入版与变化字段。比较采用明确字段列表，避免对象键顺序影响判断。文件内部重复 ID 由导入解析阶段拒绝。

新增 `applyImportPlan(existing, analysis, decisions)`，接受每个冲突 ID 的明确选择，默认保留本地版，返回新的公告数组，不修改传入数组。确认前保存导入计划所基于的当前数据快照；若本地状态已变化，则重新分析并要求重新确认。

## 交互

文件选择后打开预览对话框，显示分类数量与冲突条目。每条冲突用两个具名选项选择“保留本地”或“采用导入”，正文只作为文本展示。提供“取消”和“确认导入”，取消无需二次确认。

预览对话框应具备标题、焦点约束和键盘关闭能力；关闭后焦点回到导入入口。导入完成后以状态消息汇报实际新增、替换和跳过数量。

## 验证重点

- 乱序对象键不产生虚假冲突。
- 对同一文件重复导入不新增公告。
- 取消与非法文件不会改变内存和 localStorage。
- 选择一个冲突不会改动另一个冲突或无关公告。
- 注入 HTML 的标题与正文不会执行代码。
- 窄屏、键盘与离线环境完成整个流程。
