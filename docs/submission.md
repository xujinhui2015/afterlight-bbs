# Devpost 提交草稿

## 项目名称与赛道

**Afterlight BBS · 余烬公告板**

赛道：Resurrection。

一句话：把拨号时代的社区公告板复活成一个断网后仍可整理求助与资源的本地工具。

## 项目说明

早期 BBS 的价值在于简单、清楚、人人可以留下信息。Afterlight BBS 延续这种交流形式，用可离线运行的浏览器应用帮助社区志愿者整理求助与物资线索。

使用者可以发布求助或资源，按区域和关键词查找信息，查看带理由的规则匹配，将公告标记为已解决，并通过 JSON 文件备份或交换公告。

核心功能之一是**导入冲突预览**：当两个邻居的节点数据发生冲突时，系统会分析差异、展示逐条对比，让用户自主决定保留本地版本还是采用导入版本，取消操作不修改任何数据。

复古终端视觉保留 BBS 的辨识度，现代响应式布局让手机和键盘操作都更方便。

初版在浏览器本地运行，没有实时多人同步、在线 AI 或真实人员响应保证。它展示了弱联网场景中的信息整理流程，尚不适合作为实际救援调度系统。

## Kiro 使用说明

本项目使用 **Kiro CLI**（`kiro-cli chat`）完成了以下开发工作：

- **Steering**：`.kiro/steering/product.md` 在整个会话中始终注入，约束了语言选择、安全文本渲染、离线兼容和数据校验规范。
- **Spec 驱动开发**：按 `.kiro/specs/import-conflict-review/`（需求、设计、任务三份文档）逐步实现导入冲突预览功能。Kiro 读取规格后完成了纯函数设计（`analyzeImport`、`applyImportPlan`）、对话框 HTML、交互逻辑与 CSS 样式，并补充了 4 个测试用例。
- **验证**：Kiro 在实现后立即运行 `npm test`（14/14 通过）和 `npm run build`（构建无报错），符合 steering 中"完成改动后运行测试和构建"的要求。

详细记录见 [Kiro 工作记录](kiro-worklog.md)。
