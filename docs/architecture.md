# 架构说明

## 初版范围

应用使用 Vite 与原生 JavaScript，全部数据在当前浏览器中处理。没有后端、账户系统或第三方在线 API；页面中的公告不会自动传给其他用户。

```text
用户操作 → app.js → domain.js 校验与规则计算
                ↘ localStorage 本地保存
                ↘ JSON 导出 / 导入合并
浏览器请求 → Service Worker → 生产静态资源缓存
```

`src/domain.js` 管理公告校验、种子数据、搜索筛选、匹配、导入导出与合并。`src/app.js` 负责表单、详情、状态修改与安全 DOM 渲染。样式与界面逻辑分离。

## 数据边界

公告包含 `id`、`kind`、`title`、`category`、`district`、`body`、`status` 和 ISO 日期 `createdAt`。求助与资源采用同一结构。只有校验通过的数据才能进入公告列表。

导入是显式的本地文件操作；新公告按 ID 合并，冲突时保留当前已有版本，避免静默覆盖本地修改。这不是跨设备实时同步，也不解决多端编辑冲突。

公告文本以文本节点呈现，不能作为 HTML 执行。不要在公告中保存密码、令牌或其他不应共享的信息。导出文件包含公告正文，分享前应检查内容。

## 离线能力

生产构建会生成静态资源清单，Service Worker 依此缓存应用资源。首次加载和资源缓存需要联网；离线时读取已缓存页面，本地公告依旧由浏览器保存。

浏览器清理站点数据、隐私窗口关闭或设备丢失都可能导致本地数据不可恢复，JSON 导出用于用户主动备份。HTTPS 或 localhost 是 Service Worker 的运行前提。
